# RiskPilot Agent 记忆方案与面试学习笔记

版本：3；更新日期：2026-10-27。本文描述双服务完成态下的记忆边界：Go control plane 拥有会话、消息、账号记忆与最终提交；Python agent runtime 只消费不可变记忆快照并返回 AI 结果提案。

## 1. 记忆系统解决什么问题

模型每次调用只看到本次输入。RiskPilot 在模型外保存用户授权的信息，按轮次建立有界快照，再交给 Agent 使用。记忆系统需要同时解决持久化、来源归属、召回、更新、复核、遗忘和运行恢复一致性。

三个维度分开管理：

| 维度 | 含义 | 示例 |
| --- | --- | --- |
| 范围与生命周期 | 信息在哪些对话中使用、保存多久 | 当前会话、账号长期记忆 |
| 业务内容类型 | 信息表达什么 | 用户档案、表达偏好、业务背景 |
| 检索方式 | 如何找到相关内容 | 档案字段、关键词、受限语义排序 |

## 2. 类型与生命周期

| 机制 | 内容 | 范围与策略 |
| --- | --- | --- |
| L1 最近消息 | 最近消息原文 | 当前会话；按数量、时间和字符预算读取 |
| L2 滚动摘要 | 较早对话的压缩信息 | 当前会话；按 watermark 增量更新 |
| 账号长期记忆 | 用户明确保存的资料 | 同一账号跨会话；按开关、来源、revision 与期限筛选 |

长期记忆分为：

| `kind` / 字段 | 用途 | 默认生命周期 |
| --- | --- | --- |
| `profile.name` | 姓名或称呼 | 长期保留，仍受来源有效性和用户删除控制 |
| `profile.role` | 当前身份 / 职业 | 365 天有效，180 天复核 |
| `profile.organization` | 所属组织 | 365 天有效，180 天复核 |
| `preference` | 语言、详略、表达结构 | 长期保留 |
| `business_context` | 业务流程、系统部署与处理背景 | 默认 90 天 |

当前任务条件仍属于会话消息和摘要；法规材料属于知识库，不能被个人记忆替代。

## 3. 所有权边界

Go control plane 是记忆业务数据的唯一权威方，负责：

- `messages`、`task_summaries`、`account_memories`、`account_memory_settings` 等业务记录。
- 用户原话来源、owner、字段唯一性、revision、有效期、复核时间和召回开关。
- 保存、编辑、删除、遗忘、清空、批量原子提交和并发冲突处理。
- 每轮实际使用的记忆 ID/revision、运行快照登记和最终提交复核。
- 最终助手消息、引用与 run 终态的原子事务。

Python agent runtime 不持久化或修改这些业务记录。它只接收 Go 构造的不可变快照，可以执行：

- 记忆声明解释或字段候选提案。
- 对 Go 已授权候选的相关性排序和上下文装配。
- 会话摘要生成提案。
- Agent 推理、Evidence QA 和结果生成。

Python 的任何记忆变更、摘要或回答都只是提案；只有 Go 验证来源、版本和权限并提交后，才成为业务事实。

## 4. 保存与更新

没有保存过开关设置的账号默认关闭长期召回。保存与启用分开控制；关闭召回不妨碍用户查看、编辑或删除自己的记录。

```text
用户消息或面板输入
→ Go 验证认证、owner 与消息来源
→ 规则解析或调用 Python 生成受限字段提案
→ Go 校验 value 必须逐字来自用户原话
→ Go 检查字段唯一性、revision、期限和容量
→ Go 原子写入业务数据库
→ 返回已提交结果
```

“请记住：我叫马乐乐，是学生”可以拆为姓名和身份两条记录，各自保留对应原话。条件句、疑问句、凭据、敏感标识和控制指令不能作为可靠档案写入。

普通记忆重复保存不增加条数或自动续期。档案按账号和字段唯一管理；编辑保留 memory ID 并递增 revision。更新使用期望版本，旧页面提交不能覆盖新版本。

## 5. 每轮快照与召回

Go 在创建 run 时读取当前会话、摘要和账号记忆，并固定实际注入项：

- 先按 owner、开关、来源、期限和 revision 过滤。
- 档案按请求字段选择；偏好和业务背景按有界相关性选择。
- 只记录能完整放入预算的记忆，避免把未注入内容标成已使用。
- 把消息、摘要、记忆 ID/revision、附件版本和预算一起写入不可变 `run-execute` 快照。

Python 只能使用快照中的记忆，不能自行回查业务表扩大范围，也不能把 Agent 推断写回长期记忆。同一 attempt 中新增的记忆从下一轮生效。

## 6. 个人资料问答

“我叫什么”“我的职业是什么”等受限问题只依据有来源的档案字段和当前会话明确声明。当前会话中新声明优先于较旧资料；到复核时间的动态档案只能描述为此前保存的信息并提示确认。

Go 可以直接根据结构化档案生成确定性回答，也可以把固定快照交给 Python 生成回答提案。无论采用哪条执行路径，Go 都负责最终来源复核和消息提交。法规或混合问题必须进入 Evidence QA，不能把个人记忆当作法规证据。

## 7. 遗忘、恢复与最终事务

删除长期记忆不删除聊天历史；两者的来源类别和作用范围不同。验证跨会话遗忘时应创建新会话。

Python 返回结果提案后，Go 在最终事务中检查：

1. run、attempt 和 owner 仍匹配，运行未取消或超时。
2. 实际引用的记忆仍存在、启用、未过期且 revision 未变化。
3. 来源消息仍属于同一 owner，原话仍可验证。
4. 当前消息和附件版本仍符合本轮快照。
5. 原子写入助手消息、引用和业务终态。

检查失败时拒绝结果提案，并且不允许旧 Python checkpoint 恢复成成功。LangGraph checkpoint 只保存 AI 执行状态，不拥有业务消息或终态。

## 8. 摘要与索引

滚动摘要由 Python 生成提案，Go 保存摘要和 watermark。失败或空提案不推进 watermark。

账号记忆的业务真相始终在 Go 管理的数据中。语义索引如被使用，只负责寻找候选；结果必须回到 Go 的账号、版本、期限和来源边界验证。删除记忆后不能靠残留向量恢复内容，也不能把业务背景当作法规证据。

## 9. 面试表达

可以这样介绍：

> 我把记忆拆成 Go 业务所有权和 Python AI 计算两层。Go 保存会话、档案、来源、revision 与期限，并在每轮构造不可变快照；Python 只做相关性排序、摘要和 Agent 推理，不能直接写业务表。最终答案回到 Go 复核记忆版本和来源，并与 run 终态原子提交，所以删除、过期或更新后的旧记忆不能被 checkpoint 重新注入。

| 面试问题 | 回答重点 |
| --- | --- |
| 保存聊天记录后为什么仍需要记忆？ | 持久化解决保存，检索、摘要和快照决定信息是否进入上下文 |
| 为什么姓名与职业期限不同？ | 稳定属性与动态状态变化频率不同，期限与复核按字段设计 |
| Python 为什么不能直接写记忆？ | AI 输出是提案；来源、权限、版本与最终事务属于 Go 业务控制面 |
| 如何更新档案而不产生两个姓名？ | 账号与字段唯一管理，更新保留 ID 并增加 revision |
| 删除后为什么旧会话还能看到原话？ | 账号记忆与聊天历史是不同数据，来源类别和作用范围需要区分 |
| 如何阻止迟到答案使用旧记忆？ | Go 在最终提交前复核 run/attempt、记忆 revision、期限和来源 |
