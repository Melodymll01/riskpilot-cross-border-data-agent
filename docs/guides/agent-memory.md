# Agent 记忆使用说明

版本 2，2026-10-26。设计与面试学习笔记见 [记忆方案](../agent-memory-design-and-interview.md)。

## 类型与期限

| 类型 / 字段 | 默认期限 |
| --- | --- |
| 用户档案：姓名 / 称呼 | 长期保留 |
| 用户档案：身份 / 职业、所属组织 | 365 天有效，180 天复核 |
| 表达偏好 | 长期保留 |
| 业务背景 | 90 天 |

没有保存开关设置的账号默认关闭长期召回。已有手动设置保持原状。保存与启用分别控制，当前会话中已经提供的信息仍可作为会话上下文。

## 前端操作

登录后，在账户菜单打开“我的记忆”：

1. “自动识别”可处理明确的个人声明，如“我叫马乐乐，是学生”，拆成姓名与身份记录。
2. 也可明确选择用户档案及字段、表达偏好或业务背景。
3. 按类型默认期限保存，或选择有限有效期；姓名与偏好可主动选择长期保留。
4. 开启“在新对话中使用记忆”。
5. 列表支持搜索、行内编辑、删除；到复核时间的档案会显示待复核。
6. “确认仍有效”或“更新有效期”会增加版本并刷新期限。清空全部需要再次确认。

## 聊天命令

| 操作 | 示例 |
| --- | --- |
| 保存档案 | `请记住：我叫马乐乐，是学生` |
| 保存偏好 | `请记住：回答优先列出法规依据` |
| 查看 | `查看我的记忆` |
| 开启 / 关闭 | `开启记忆` / `关闭记忆` |
| 更新职业 | `请更新我的职业：工程师` |
| 更新姓名 | `请更新我的姓名：我叫王晓` |
| 按原文更新 | `请更新记忆：回答简洁一点 => 回答详细解释` |
| 按原文遗忘 | `请忘记：回答详细解释` |
| 遗忘姓名 | `请忘记我的姓名` |
| 清空 | `请清空我的记忆` |

普通记忆重复保存不会增加条数或续期。档案按账号和字段唯一管理，明确更新保留同一 ID、增加版本。模糊目标有多条候选时，要求明确指定。

## 个人信息问答

开启后，新建会话可问“我叫什么”“我的职业是什么”“我的身份是什么”“我的公司叫什么”“我是谁”。答案依据可验证的档案值，并显示记忆来源原话。

当前会话的新声明优先于较旧资料；更新档案时也按明确声明时间选择来源。当前消息只用于会话，不自动写回长期记忆。

关闭长期召回或缺少档案时，会明确说明。到复核时间的身份只描述之前保存的状态，并要求确认。法规与混合问题继续走原有证据链路，不根据个人记忆直接判断合规。

## 存储、迁移与遗忘

Go control plane 在业务存储的 `account_memories` 中保存资料、来源、版本、期限和复核时间。Go 每轮固定实际引用，并在恢复和最终提交前检查版本与来源；Python agent runtime 只使用快照，不直接写入或回查该表。

旧记录初始化时升级到 schema 2，升级前自动在数据库旁的 `backups/` 保存 SQLite 副本。未过期且明确的旧个人声明可拆为档案，不复活过期记录，也不改变已有手动开关。

删除长期记忆不会删除聊天历史，验证跨会话遗忘时应新建会话。当前会话引用与账号记忆引用会分别标明来源。

业务背景仍使用关键词召回。向量语义召回尚未接入；未来可复用现有 Embedding 和排名融合，但使用独立集合并回读 SQLite 校验。

## 验证入口

```bash
RUN_LIVE=0 make ci PY=.venv/bin/python
```

验证覆盖 Go 记忆 CRUD/版本/最终提交、跨服务快照合同、Python 快照消费、浏览器操作和失效引用拒绝。`services/agent-runtime/tests/` 中的模型与召回测试只证明 AI 执行逻辑，不是业务数据所有权或真实模型效果证据。
