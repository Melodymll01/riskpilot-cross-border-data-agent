# ADR-016：案件证据与规则快照

- 状态：已接受
- 日期：2026-08-06

## 背景

当前上传文档以 `source_name` 作为主要身份，完成入库后删除临时原文件，附件 ID 只被
拼进提示词。系统难以表达文档版本、案件绑定、页级证据和历史评估使用的法规版本。

## 决策

1. 文档采用 `Document + DocumentVersion` 两层模型。
2. 原始文件持久化并记录 SHA-256、解析器版本、页数和对象存储位置。
3. 通过 `CaseDocument` 显式建立文档与案件的关系。
4. Chunk 必须携带 Workspace、Case、Document、Version、页码和章节元数据。
5. `CaseFact` 与 `EvidenceSpan` 分离，事实记录结构化值，证据记录原文定位。
6. 正式 Assessment 保存事实、法规、规则和模型配置快照。
7. Assessment 发布后不可覆盖；重评产生新版本，旧版本标记为 `superseded`。
8. 法律门槛由版本化 `PolicyRule` 计算，不散落在 Prompt 或临时 Python 分支中。

## 结果

- 每个结论可以追溯到原始材料和法规条款。
- 文档或法规更新后可以判断哪些案件需要重评。
- 删除和被遗忘权需要覆盖对象存储、Chunk、向量、事实引用和运行状态。
- 文档处理需要从同步请求迁移为可重试的后台 Job。
